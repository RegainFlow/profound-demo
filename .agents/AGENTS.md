# Agent Harness Instructions

- Skills must describe when to use them and what output they produce.
- A skill should earn its place by retiring repeated review pain.
- Keep skills narrow; prefer deterministic rules when the behavior is mechanically checkable.
- Each skill must have an owner and a maintenance trigger.
- Route brand, API, testing, review, and PR-size questions through `docs/`.
- Customer-facing UI and report-copy changes remain human-reviewed even when deterministic gates pass.
